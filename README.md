# Фаэтон · Минеральные Воды / КМВ

Сайт «Фаэтон КМВ»: 8 моделей, классы и назначение машин, даты/время (МСК), расчет по начатым суткам, передача заявки в Telegram. Модели, тарифы и залоги сверены с faetonkmv.ru 31.10.2026; наличие подтверждает менеджер. Изображения автомобилей и мест — художественные иллюстрации, не доказательство фактического наличия и состояния автомобиля.

## После перезагрузки компьютера

Дважды нажмите `START-SITE.cmd`, затем `START-BOT.cmd`. Оба окна оставьте открытыми. Сайт: http://127.0.0.1:4173/, администратор: http://127.0.0.1:4173/admin.html, API: http://127.0.0.1:3000. Ключ администратора находится в `backend/.env` в строке ADMIN_TOKEN; BOT_TOKEN — отдельный ключ Telegram. Секреты не публикуются.

При недоступности Telegram сервер сайта продолжает работать и повторяет попытки соединения с ботом. Публичный сервер пока не размещён; локальные адреса доступны только на этом компьютере. Приём документов отключён.

## Запуск сайта из GitHub

В Settings → Pages выберите Source: GitHub Actions. Workflow `.github/workflows/pages.yml` публикует `dist/` при push в main. Ожидаемый адрес после успешного развертывания: https://lunadark323-gif.github.io/My-first-web-coding-project-repository/ (не подтверждение публикации).

GitHub Pages для приватного репозитория требует подходящего платного тарифа. Не делайте репозиторий публичным без проверки содержимого. В GitHub Free можно отдельно согласовать публичный репозиторий только для кода/фронтенда. Даже при приватном репозитории обычный сайт Pages может быть публичным.

Локальная проверка: `node preview.mjs`. При открытии с 127.0.0.1 или localhost сайт использует API http://127.0.0.1:3000. На публичном домене нужно отдельно настроить HTTPS API в `dist/config.js`.

## Бэкенд и Telegram

GitHub хранит код, но Pages не выполняет сервер. Разместите `backend/` на сервере в РФ с Node.js 24+, HTTPS и доступом к Telegram API. `cd backend`, затем `npm install`. Скопируйте `.env.example` в `.env`, заполните значения и выполните `npm start`.

Создайте бота у @BotFather и установите BOT_TOKEN только на сервере. Сгенерируйте DATA_KEY: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`. ADMIN_TOKEN — независимый случайный секрет. Не коммитьте `.env`, базы, договоры, отчеты, паспортные данные. Защитите ключи и резервные копии, настройте файрвол и ограничение запросов на reverse proxy. База и ключ должны резервироваться раздельно.

В `dist/config.js` укажите `apiBase` (HTTPS API) и `botUsername` (без @). FRONTEND_ORIGIN — origin GitHub Pages без пути. PUBLIC_ORIGIN — точный HTTPS origin API без завершающего слеша. Через reverse proxy проксируйте на 127.0.0.1:3000. Запускайте только один экземпляр polling-бота.

Сайт создает случайный токен заявки без ФИО и паспортных данных. Бот связывает его с приватным чатом и дает короткоживущую ссылку на форму на вашем сервере. Форма сохраняет данные с AES-256-GCM; ссылка становится недействительной после отправки. Telegram не используется для передачи паспортов. Согласие, его версия и время сохраняются. Сбор отключен до заполнения настроек оператора/юридических текстов и COLLECTION_ENABLED=true. Это технический выключатель, а не подтверждение соблюдения закона.

## Менеджер и файлы

API администратора требует заголовок `Authorization: Bearer <ADMIN_TOKEN>`. Не помещайте ADMIN_TOKEN во фронтенд. `/admin/bookings` возвращает заявки. `POST /admin/confirm` с JSON `{"id":"номер"}` подтверждает заявку после проверки менеджером; пересекающиеся подтвержденные периоды одного авто блокируются транзакцией. Модель использует одну машину на каждый id; перед запуском внесите фактические автомобили с уникальными id.

`GET /admin/report.xlsx` скачивает Excel с заявками, ФИО, сроками, статусами и статистикой. Паспорт и права в отчет не включаются. Суммы расчетные, не фактическая выручка. `GET /admin/contract/<id>` возвращает HTML-файл с двумя экземплярами проекта договора для печати или сохранения в PDF. Админ-панель реализована: заявки, клиенты, статистика по месяцам, выгрузка Excel, смена статуса, проверка бота. Платежи и учет фактических оплат пока не реализованы.

## До коммерческого запуска

Проект договора явно помечен черновиком и не готов к подписанию: нужны реквизиты сторон, фактические VIN/номера/СТС, условия оплаты и залога, страховка, территория, ограничения, ответственность и акт приема-передачи. Финальную редакцию согласуйте с юристом. Письменная форма аренды ТС без экипажа предусмотрена ст. 643 ГК РФ: https://www.consultant.ru/document/cons_doc_LAW_9027/85311aad71f6880abacfdad4fcf4c8a63af852ec/

Определите правовые основания и минимальный набор данных, сроки хранения и удаления, порядок отзыва согласия, уведомление Роскомнадзора при применимости, меры защиты и локализацию баз по 152-ФЗ. Опубликуйте отдельные реальные тексты политики и согласия, проверьте правила использования внешнего мессенджера. Полное соответствие законам не обеспечивается одним шаблоном. Скан-копии документов намеренно не собираются; необходимость их хранения должна быть обоснована отдельно. Для сохраненных заявок с документами автоматическое удаление пока не реализовано: до включения сбора настройте регламент и удаление по срокам/запросам. Информация: https://pd.rkn.gov.ru/

## Проверка

`node --test tests/*.test.mjs` проверяет расчет, даты, экранирование, пошаговый выбор в боте, точное время, сохранение заявки и привязку заявки с сайта к одному Telegram-чату. Для Excel нужна зависимость exceljs. Реальный ответ в Telegram требует работающего соединения с Telegram API. Получение документов дополнительно требует настроенного HTTPS-сервера и включения сбора; сейчас оно отключено.
